This talk is about a GUI I made to ease using and adding to the pymolshortcuts library that I published in 2020.
I have used this GUI to bring the shortcuts into the AI era.

In this case, a shorcut is really an alias to a Python function that executes several to many lines of code.
I did not call them aliases because there is a built-in PyMOL function called alias that stores aliases only in the current session.
This pymolshortcyts library has been popular whith people who do not fear the command line.

I developed this GUI for the current PyMOL 3.s series to lower the barrier to using the PyMOL shortcuts for people who fear using the command line.
I also included two kinds of interfaces to large language models.

The core message is that my library of curated shortcuts and AI code generation are complementary. 
The shortcuts are fast and reliable whereas the AI tools help answer questions about the shortcuts and they can generate new shortcuts.

\section{The accessibility problem}
%--------------------------------------------------- Slide 10: The barrier
\begin{frame}{\underline{F}ear \underline{O}f the \underline{C}ommand \underline{L}ine (FOCL)}
\begin{columns}[T]
      \begin{column}{0.38\linewidth}
            \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item Many users prefer pulldown menus.
    \item PML and Python code intimidates many users.
    \item List of shortcuts in the command history window may frighten some users.
  \end{itemize}
\end{column}
     \begin{column}{0.58\linewidth}
      \begin{figure}

 \end{columns}

\note{
My primitive solution to this problem was to print the list of Shortcuts and their description to the command history window.
In the PyMOL three-point X versions, the command history window has been moved to a new location below the viewport.
You could still copy a code that's been printed to the command history window and paste it into a script file.

However, the command history window looks too much like the PyMOL prompt and it scares many users who fear the PyMOL prompt.
}

\section{Design goals for plugin's GUI}
%--------------------------------------------------- Slide 12: The solution
\begin{frame}{Design goals for pymolshortcuts-manager}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item [  ] The PyQt5-based plugin must remains compatible with the PyMOL 3.x series.
    \pause
    \item [  ] Point-and-click installation and execution of the curated shortcut library.
        \pause
    \item [  ] The original shortcuts must remain functional, so experienced users keep their existing workflows.
        \pause
    \item [  ] Direct access to documentation.
    
    \item [  ] Ease code reuse by copying code to clipboard.
        \pause
    \item [  ] Query the PyMOL shortcuts via RAG.
        \pause
    \item [  ] Use agent harnesses inside PyMOL. 
        \pause
    \item [  ] Must be able to open GUI with a shortcut.
  \end{itemize}
\end{frame}
\note{ These were the design goals that I had in mind.
The first requirement was that the plug-in be compatible with the PyMOL 3X series.
There is a PT six module available so the length of the lifespan of this plug-in could be shortened by a switch to that a module in the future.
The other design requirement was point-and-click installation, select selection and execution of the Shortcuts.
The gooey also had to support direct access to the documentation and the source code from inside of the gooey.
The user needed the option of copying to the clipboard either the PNL or the python version of the code.
The guy also needed to bail provide access to AI in the form of a Chatbot and in the form of support for agent harnesses.
The first kind of AI support can be used to answer questions about shortcuts and define shortcuts it can also be used to generate new shortcuts the second kind of AI support is for greater autonomous use of AI to generate images.
Last but not least experienced users of the command line version it still needed access to the command line shortcuts and they also needed to have access to the gooey by entering a shortcut at the PyMOL prompt.
.}

\section{Why shortcuts still matter}

%--------------------------------------------------- Slide 17: Speed
\begin{frame}{Advantage 1: speed and workflow efficiency}
  \small\textit{The central question: why keep curated shortcuts when an AI
  chatbot can generate PyMOL commands on demand? The next slides give the
  concrete answer.}
  \vspace{4pt}
  \begin{columns}[T]
    \begin{column}{0.54\linewidth}
      \begin{itemize}[font=$\bullet$\scshape\bfseries]
        \item A shortcut runs in under one second because it is pre-compiled.
        \item An AI round trip takes 10 to 30 seconds: prompt, transmit,
              inference, copy, paste, validate.
        \item Interactive sessions run dozens to hundreds of commands, so each
              delay compounds and breaks flow state.
      \end{itemize}
    \end{column}
    \begin{column}{0.44\linewidth}
      \figph[\linewidth]{Figure 3: workflow execution times, shortcut versus
      AI generation, error bars over 50 trials}
    \end{column}
  \end{columns}
  \vfill
  \footnotesize\textit{Note: the timing numbers require a documented benchmark
  before publication.}
\end{frame}
\note{Speed is the headline empirical claim, so be careful. Present the numbers
as the goal of a benchmark that must be documented. Reviewers flagged that
Figure 3 currently lacks a methods section, so either run a real benchmark or
label the numbers as illustrative estimates.}

%--------------------------------------------------- Slide 19: Reliability
\begin{frame}{Advantage 2: reliability and scientific rigor}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item Shortcuts are tested, debugged code that behaves deterministically.
    \item AI-generated code can hallucinate command names, invalid
          parameters, or deprecated syntax.
    \item Using AI code requires a validation cycle of testing, debugging, and
          verification that erodes the time savings.
    \item Integration tests detect when PyMOL API changes break a shortcut,
          enabling rapid fixes.
  \end{itemize}
  \vfill
  \small We describe this as high, tested reliability rather than guaranteed
  correctness, because no code is absolutely guaranteed.
\end{frame}
\note{Soften the absolute language deliberately. Say tested reliability, not
guaranteed correctness. The point still stands: validated code beats freshly
generated code for routine tasks. Cite code-correctness evaluation work in the
paper.}

%--------------------------------------------------- Slide 20: Reproducibility
\begin{frame}{Advantage 3: reproducibility and stability}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item A version-pinned shortcut library can be downloaded and rerun
          exactly by other investigators.
    \item Git provides permanent, immutable references.
    \item AI-generated code drifts: models update, sampling varies, services
          may be discontinued, so there is no stable reference point.
    \item The History tab records which shortcuts ran with which parameters,
          giving an exportable provenance trail.
  \end{itemize}
\end{frame}
\note{Reproducibility is a strong, defensible advantage. Tie it back to the
History tab. To make the argument airtight, the paper should archive a versioned
release with a DOI and register an RRID, which the tool currently lacks.}

%--------------------------------------------------- Slide 21: Cost/offline/security
\begin{frame}{Advantage 4: cost, offline access, and data security}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item \textbf{Cost:} shortcuts are free and open source with no per-query
          charge.
    \item \textbf{Offline:} shortcuts run locally, which matters for field
          stations and restricted-network facilities.
    \item \textbf{Security:} local execution keeps proprietary or unpublished
          structures on the user's machine.
  \end{itemize}
  \vfill
  \small\textit{Honest caveat: our own AI Assistant tab uses a paid API and an
  internet connection, so it shares these very trade-offs when enabled.}
\end{frame}
\note{Include the honest caveat out loud. The AI tab incurs the costs we
criticize. Acknowledging this builds credibility and answers the obvious
reviewer objection before it is raised.}

%--------------------------------------------------- Slide 22: Education
\begin{frame}{Advantage 5: educational value}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item The View Code button turns every shortcut into a working example of
          correct syntax and parameter use.
    \item Users progress from point-and-click, to reading the code, to writing
          their own functions.
    \item Exported histories from expert sessions become concrete teaching
          material.
    \item AI-generated code often arrives as a black box that does not build a
          mental model.
  \end{itemize}
  \vfill
  \small\textit{Analogy: shortcuts are a glass-walled kitchen. You watch the
  cooking, so you learn to cook. A pure AI answer hands you the finished dish.}
\end{frame}
\note{Education is where curated tooling clearly beats an oracle. The
glass-walled kitchen analogy resonates with teachers. Frame this as scaffolding
that closes the gap between GUI-only use and scripting.}

%--------------------------------------------------- Slide 23: Curation
\begin{frame}{Advantage 6: expert curation and community validation}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item Shortcuts encode expert decisions about defaults, parameters, and
          error handling.
    \item Popular shortcuts have been exercised by many researchers, so bugs
          surface and get fixed.
    \item Consistent conventions across shortcuts reduce cognitive load.
    \item Individually generated AI code receives no comparable cross-user
          validation and varies in style.
  \end{itemize}
\end{frame}
\note{This is the crowd-tested argument. Community use is a form of validation
that a one-off generation cannot match. Keep it brief because it overlaps with
the reliability slide.}

%--------------------------------------------------- Slide 24: Interactive workflows
\begin{frame}{Advantage 7: built for interactive workflows}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item \textbf{Command chaining:} shortcuts compose, so outputs feed the
          next step (select, represent, color, orient, ray trace).
    \item \textbf{State awareness:} shortcuts operate within PyMOL's
          persistent state and can assume context.
    \item \textbf{Tight loops:} change, evaluate, adjust, all within one
          environment.
    \item AI code is stateless and must be described anew each query, which
          produces defensive, less efficient code.
  \end{itemize}
\end{frame}
\note{The state point is subtle but important for a technical crowd. The AI has
no view into the current session, so it must guess. Shortcuts leverage what
already exists in memory.}

%--------------------------------------------------- Slide 25: Sustainability
\begin{frame}{Advantage 8: sustainability and community ownership}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item Open-source code hosted on GitHub remains available and is easily
          migrated elsewhere.
    \item No subscription to lapse and no company to pivot away.
    \item If maintenance stops, any community member can fork and continue.
    \item Commercial AI services concentrate control in one entity whose
          priorities may diverge from scientific needs.
  \end{itemize}
\end{frame}
\note{Sustainability closes the advantages list. The fork option is the key
guarantee. Do not overstate the fragility of AI services, just note the genuine
uncertainty about long-term availability and pricing.}

%--------------------------------------------------- Slide 31: Summary
\begin{frame}{Summary}
  \begin{itemize}[font=$\bullet$\scshape\bfseries]
    \item The pymolshortcuts-manager plugin gives point-and-click access to
          over 233 curated PyMOL 3.x shortcuts through six tabs.
    \item Shortcuts provide instant execution, tested reliability,
          reproducibility, offline operation, and long-term stability.
    \item A RAG-based AI Assistant grounds answers in verified documentation
          and reduces, though does not eliminate, hallucination.
    \item Shortcuts and AI are complementary, and integrating both in one
          interface is stronger than either alone.
  \end{itemize}
\end{frame}
